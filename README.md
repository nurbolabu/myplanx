# MyPlanX

Telegram-планировщик для личного использования, пары и маленькой команды.

## Уже есть

- личное пространство, создаваемое при `/start`;
- Mini App в стиле iOS: день, планы, покупки и бюджет;
- создание и завершение задач;
- общие пространства для пары/семьи с одноразовой ссылкой-приглашением на 7 дней;
- назначение исполнителя и напоминание к задаче на точные дату и время;
- список покупок;
- запись доходов и расходов;
- локальная SQLite-база, исключённая из Git.

## Запуск

1. Скопируйте `.env.example` в `.env` и добавьте токен от BotFather.
2. Для разработки: `npm run dev`.
3. Откройте `http://localhost:5173` в браузере для проверки интерфейса. В Telegram Mini App будет автоматически авторизован по Telegram ID.

## Подключение к Telegram

Telegram открывает Mini App только по публичному HTTPS-адресу. Перед тестом в самом Telegram:

1. Соберите проект: `npm run build`.
2. Разместите сервер по HTTPS.
3. Укажите публичный адрес в `WEB_APP_URL`.
4. В BotFather настройте Main Mini App на этот же адрес.
5. Отправьте боту `/start` и нажмите «Открыть планер».

Токен хранится только в `.env`; никогда не добавляйте его в Git.

Для настоящего пользователя напоминание придёт в его личный чат с ботом. Поэтому каждый участник должен хотя бы один раз нажать `/start`.

## Деплой

Для MVP подойдут Railway или Render с постоянным сервисом: бот использует long polling и должен оставаться запущенным. Docker-конфигурация уже добавлена.

Для Railway добавлен `railway.toml` с health-check на `/health`.

В переменных окружения сервиса задайте:

- `BOT_TOKEN` — новый токен от BotFather;
- `WEB_APP_URL` — HTTPS-адрес этого же сервиса, например `https://myplanx.up.railway.app`;
- `PORT=3000`.

После первого деплоя укажите этот HTTPS-адрес как Main Mini App в BotFather. Не используйте Vercel serverless для текущей версии: постоянный long polling там не работает.
